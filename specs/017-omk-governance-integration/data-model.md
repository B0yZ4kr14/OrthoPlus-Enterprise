# Data Model: OMK Governance Integration

**Feature**: 017-omk-governance-integration

## Overview

This feature does not introduce new application data models. Instead, it operates on existing metadata structures:

- **GitNexus Graph**: Read-only code intelligence graph (33k+ nodes, 70k+ edges)
- **SpecKit Artifacts**: Filesystem-based spec documents in `specs/`
- **OMK Memory Graph**: Goal/ontology nodes in `.omk/memory/`

## Entities

### GitNexus Symbol Node

| Attribute | Type | Description |
|-----------|------|-------------|
| `id` | string | Unique symbol identifier (e.g., `backend/src/modules/auth/api/AuthController.ts::AuthController`) |
| `name` | string | Symbol name (e.g., `AuthController`) |
| `type` | enum | `function`, `class`, `interface`, `variable`, `type`, `module` |
| `filePath` | string | Relative path from repo root |
| `lineStart` | number | Line number where symbol is declared |
| `lineEnd` | number | Line number where symbol ends |

**Relationships**:
- `CALLS` → another Symbol Node (function/method calls)
- `IMPORTS` → another Symbol Node (module dependencies)
- `EXTENDS` → another Symbol Node (inheritance)
- `PART_OF` → Execution Flow Node

### SpecKit Feature Artifact

| Attribute | Type | Description |
|-----------|------|-------------|
| `featureId` | string | Directory name (e.g., `017-omk-governance-integration`) |
| `featureNum` | number | Sequential number (e.g., `17`) |
| `shortName` | string | Machine-friendly name (e.g., `omk-governance-integration`) |
| `status` | enum | `draft`, `clarified`, `planned`, `in_progress`, `verified`, `shipped` |
| `specPath` | path | Absolute path to `spec.md` |
| `planPath` | path | Absolute path to `plan.md` |
| `tasksPath` | path | Absolute path to `tasks.md` |
| `branch` | string | Associated git branch |

**State Transitions**:
```
draft → clarified → planned → in_progress → verified → shipped
   ↑______________|          |______________|
   (revert on scope change)  (revert on gate failure)
```

### OMK Goal Node

| Attribute | Type | Description |
|-----------|------|-------------|
| `goalId` | string | UUID generated by OMK |
| `title` | string | Human-readable goal title |
| `objective` | string | What the goal aims to achieve |
| `status` | enum | `active`, `paused`, `completed`, `failed` |
| `riskLevel` | enum | `low`, `medium`, `high` |
| `evidence` | array | List of evidence entries (criterionId, passed, message, ref) |

**Relationships**:
- `HAS_CRITERION` → Success Criterion Node
- `HAS_ARTIFACT` → Artifact Node (file paths, URLs)
- `ASSIGNED_TO` → Squad Agent Node

## Validation Rules

1. Every SpecKit feature MUST have a valid `spec.md` with all mandatory sections before transitioning to `planned`.
2. Every OMK goal MUST have at least one success criterion with a measurable outcome.
3. GitNexus index MUST be fresher than 24 hours for impact analysis to be considered reliable.
