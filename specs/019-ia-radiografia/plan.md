## Summary

Reverse-engineer and document the existing `ia_radiografia` module (AI dental radiograph analysis), then fix critical gaps: storage upload is faked, AI runs synchronously, the frontend cannot call the review endpoint, and enum/type mismatches exist between frontend and backend.

## Known Gaps & Risks

| ID | Issue | Severity | Location | Fix Required |
|----|-------|----------|----------|--------------|
| **GAP-001** | Storage upload is faked — local path placeholder | 🔴 Critical | `controller.ts:50-52` | Implement real upload to MinIO/S3 |
| **GAP-002** | AI processing runs synchronously inline | 🟡 High | `controller.ts:82` | Move to background worker/queue |
| **GAP-003** | Frontend cannot call review endpoint — missing `assinatura_digital` | 🔴 Critical | `useRadiografia.ts` ↔ `controller.ts` | Add signature field to frontend |
| **GAP-004** | `TipoRadiografia` enum mismatch frontend ↔ backend | 🟡 High | `radiografia.types.ts` ↔ `schema.prisma` | Sync enums (add OCLUSAL, LATERAL; remove CEFALOMETRICA, TOMOGRAFIA or add to Prisma) |
| **GAP-005** | No `problema_radiografico` table — problems stored only in JSON | 🟡 High | `schema.prisma` | Either create table or update spec to document JSON-only storage |
| **GAP-006** | No GET endpoint for audit trail retrieval | 🟡 High | `router.ts` | Add `GET /audit/:analiseId` endpoint |
| **GAP-007** | Rate limiter uses in-memory Map (not Redis) | 🟡 High | `iaRateLimiter.ts` | Replace with Redis-backed limiter |
| **GAP-008** | `IAEncryptionService` falls back to hardcoded dev key | 🔴 Critical | `IAEncryptionService.ts` | Remove fallback, fail hard if env var missing |
| **GAP-009** | Frontend Zod schema field names don't match DB columns | 🟡 Medium | `radiografia.types.ts` | Rename `status_analise` → `status`, `revisado_por_dentista` → `revisada` |
| **GAP-010** | Frontend expects `sugestoes_tratamento` with `prioridade` — AI service doesn't produce them | 🟡 Medium | `LocalAIService.ts` ↔ `AnaliseComplete` | Update AI prompt or adjust frontend types |

## Complexity Tracking

> This is a brownfield feature — code exists but has critical gaps.

| Violation | Why Needed | Simpler Alternative Rejected Because |
|-----------|------------|-------------------------------------|
| Synchronous AI processing | Current implementation | Background queue requires Redis + worker infrastructure (GAP-002) |
| JSON-only problem storage | No dedicated table exists | Creating a normalized table requires migration + frontend updates (GAP-005) |
| Hardcoded encryption fallback | Dev convenience | Removing it breaks local dev without env setup (GAP-008) |
