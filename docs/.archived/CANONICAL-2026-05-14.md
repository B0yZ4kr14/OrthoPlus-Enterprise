## 1. Visão Geral

O **OrthoPlus Enterprise** é um monorepo full-stack de gestão odontológica com:

- **Frontend**: React 18.3 + Vite 8 + Tailwind CSS 3.4 (porta 3000 dev / 5173 legacy)
- **Backend**: Node.js 20 + Express 4 + Prisma 6 + PostgreSQL 16 (porta 3005)
- **Agent Service**: Python 3.14 + FastAPI + Agno 2.5 (porta 8000)
- **Banco de Dados**: PostgreSQL 16, 180 tabelas, 17 schemas (16 custom + public), role `orthoplus`
- **Cache**: Redis 7 (autenticado, porta 6379)
- **Proxy**: Nginx + Cloudflare (TLS)

## 3. Convenções de Código

### TypeScript (Backend)
- ES Modules (`import/export`)
- Strict mode (tipagem obrigatória)
- Async/await (nunca callbacks)
- Error handling via `ApiError` de `@/errors/ApiError`
- Todo router deve usar `clinicGuard` middleware
- Preferir Prisma Client sobre `queryRaw`

### TypeScript (Frontend)
- Custom hooks em `hooks/` ou `components/*/use*.ts`
- API Client: `apiClient` de `lib/api/apiClient.ts`
- Date utils: `lib/utils/date.utils.ts` (não `date-fns` direto)
- Auth: `useAuth()` do `contexts/AuthContext.tsx`
- **NUNCA** adicionar mais `as any` ou `@ts-ignore`
- `apps/web/src/types/database.ts` é **autogenerated** — nunca editar manualmente

### Bash (Scripts)
- Shebang: `#!/bin/bash`
- `set -e` na segunda linha
- Funções de log coloridas padronizadas

## 4. Comandos Essenciais

```bash
# Root
pnpm install
pnpm dev          # Turbo dev (frontend 3000, backend 3005)
pnpm build        # Turbo build (frontend + backend + shared-types)
pnpm lint
pnpm type-check

# Backend individual
cd backend && pnpm build      # tsc + tsc-alias
cd backend && pnpm dev        # tsx watch
cd backend && pnpm test       # jest (367 tests, 17 suites)

# Frontend individual
cd apps/web && pnpm dev       # Vite dev (porta 3000)
cd apps/web && pnpm build     # Vite build → dist/

# Agent Service
cd agent-service && python src/main.py   # FastAPI (porta 8000)
```

## 6. Rotas e Endpoints

### Base URL
- Local: `http://localhost:3005/api`
- Produção: `https://tsiapp.io/api` (via nginx proxy)

### Auth (público)
- `POST /api/auth/token` — Login
- `POST /api/auth/register` — Registro staff
- `POST /api/auth/reset-password` — Reset senha
- `POST /api/auth/patient-auth` — Auth paciente
- `GET /api/auth/me` — Perfil atual

### Health Check (público)
- `GET /health` — Status do servidor
- `GET /api/health` — Alias (também público)

### Módulos (requerem JWT + clinicGuard)
- `GET/POST/PATCH/DELETE /api/{modulo}/*` — CRUD por módulo

## 7. Segurança

- **clinicGuard**: Valida `req.user.clinicId` em TODOS os routers
- **Rate Limiting**: Auth (10/15min), Upload (50/h), API (500/15min)
- **CSRF**: Origin check + sameSite=strict
- **Helmet**: Headers de segurança HTTP
- **JWT**: 256-bit secret, expira em 24h
- **Secrets**: `backend/.env` e `ecosystem.json` removidos do git
