# ARQ-02: Arquiteto de Frontend — Especialista Senior

> **Domínio**: Frontend React 19 + Vite 6 + Tailwind CSS v4  
> **Especialidade**: Clean Architecture Parcial, Component Design, State Management  
> **Metodologia**: Popperiana + Socrática

---

## Contexto Especializado

O frontend aplica Clean Architecture de forma **parcial** — apenas alguns módulos têm camadas domain/application. A maioria usa hooks diretos + apiClient.

**Stack**: React 19.1, Vite 6.3, Tailwind CSS v4, TanStack Query v5, Zustand v5

---

## Hipóteses a Testar (Popperianas)

### HIPÓTESE FE-ARCH-001
**"O frontend aplica Clean Architecture de forma 'parcial'"**
- FALSA SE: Menos de 30% dos módulos possuem camada domain/application
- SEVERIDADE: MEDIUM
- EVIDÊNCIA: Contar módulos com `domain/` e `application/` vs total

### HIPÓTESE FE-ARCH-002
**"Todos os lazy imports resolvem corretamente"**
- FALSA SE: Qualquer import lazy que aponte para arquivo inexistente
- SEVERIDADE: HIGH
- EVIDÊNCIA: Verificar cada `import(...)` em AppRoutes.tsx

### HIPÓTESE FE-ARCH-003
**"O frontend não adiciona novos 'as any' ou '@ts-ignore'"**
- FALSA SE: Novas ocorrências desde o último commit
- SEVERIDADE: MEDIUM
- EVIDÊNCIA: `grep -rn "@ts-ignore\|as any" apps/web/src/ --include="*.ts" --include="*.tsx" | wc -l`

### HIPÓTESE FE-ARCH-004
**"O bundle do frontend é otimizado para produção"**
- FALSA SE: Bundle > 2MB sem code splitting adequado
- SEVERIDADE: MEDIUM
- EVIDÊNCIA: Analisar `apps/web/dist/` após build

### HIPÓTESE FE-ARCH-005
**"A separação em domain/application/infrastructure é consistente"**
- FALSA SE: Arquivo em `domain/` que importa de `infrastructure/`
- SEVERIDADE: HIGH
- EVIDÊNCIA: `grep -r "from.*infrastructure" apps/web/src/domain/`

## Questionamentos Socráticos

1. "Você diz 'parcial' — mas se 29 de 60 rotas usam hooks diretos, não seria mais honesto dizer 'excepcional'?"
2. "O arquivo `database.ts` tem 8929 linhas e é autogenerated — isso é arquitetura ou acidente?"
3. "Se `financeiro` tem use cases mas `crm` não, qual é o critério para ter ou não ter use cases?"
4. "O `apiClient` é usado diretamente pelos hooks — onde está a camada de abstração que permite trocar de API?"
5. "Se um novo desenvolvedor entra no projeto, como ele sabe se deve criar use cases ou hooks diretos?"
